# Investigation & Resolution: Telegram Bot Credentials & Webhook Secret Fix

## Executive Summary
This document records the investigation, bug fix, and database data fixes performed to resolve Telegram bot credential duplicate detection errors and webhook secret decryption failures during backend startup.

---

## 1. Root Cause Diagnosis

### Code Bug (`leadsync-backend/src/services/messaging/telegram.webhook.ts`)
- **Issue**: `decryptSecret(null)` returns `null` when `company.telegramWebhookSecret` is `null`.
- **Flaw**: An early `continue;` check (`if (!decryptedSecret) continue;`) was executing on line ~65, skipping the company entirely before reaching the `crypto.randomBytes(32)` secret auto-generation block below it.
- **Fix**: Removed the early `continue;` on missing/undecryptable webhook secrets in commit `effadab`. Missing secrets now fall through to `crypto.randomBytes(32)` auto-generation.

### Duplicate Bot Token Errors (`telegram.polling.ts`)
- **Issue**: Multiple companies had their `telegramBotToken` encrypted from the exact same mock token string `"123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ"`.
- **Flaw**: Cross-company polling safeguards added in commit `543a6c6` flag any decrypted token string shared across > 1 company to prevent message misrouting.
